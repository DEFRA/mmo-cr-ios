# Validation copy not covered by the September 2026 validation-messages change

This is the reference list produced under **Q8** of the catch-record validation-messages piece of
work (see `docs/design-specs/` for the related design spec and the working-framework approval
thread). It records every validation/error message in the app **that was left unchanged**, so the
gap is visible and can be picked up as a deliberate future content pass rather than discovered by
accident.

Nothing in this document requires action as part of this change. It is a scope record, not a defect
list — though two rows are flagged below as candidates for the next content pass.

## Flagged for a future content pass

These two are the kind of generic, context-free message the new copy in this change deliberately
moved away from (see `catchRecord.tripDate.*`, `catchRecord.species.*` for the pattern to follow —
name the field, name what's being recorded):

1. **`catchRecord.gear.measurement.validation.wholeNumber`** — "Enter a whole number" gives no field
   name and no context. Compare to the new `catchRecord.species.weight.validation.wholeNumber`
   ("Weight for %@ must be a whole number").
2. **Port/vessel selection messages** ("Select the port you left from" / "Select a vessel") use a
   different sentence shape to the newly adopted "Select the gear used on this trip" / "Select a
   statistical subrectangle" pattern. Not wrong, just inconsistent — worth reconciling for a
   uniform voice across the journey.

## How this list was produced

Generated by reading every `*Validation.swift` / `*ViewModel.swift` file's error-key producer in
`record-catch/Features/CatchRecord/` and cross-referencing against `Resources/Localizable.xcstrings`,
as part of the validation-messages change (September 2026). Update this list if any of the above
screens are revisited, or delete the corresponding row once a message is brought in line with the
new content pattern.
